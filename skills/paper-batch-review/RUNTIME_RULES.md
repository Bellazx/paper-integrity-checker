### 运行时复核规则

目标：对高风险初检结果做严格复核。自动报告只是线索，必须先形成独立判断，再验证 report.json。结论只能是“建议高风险”或“建议低风险”。不确定、关键证据无法核验、或低风险解释无法覆盖全部必查项时，保持高风险。

反惯性要求：不能把“初检高风险”本身当作证据，不能为支持初检结论倒推异常；只有独立核验后的实质问题才支持高风险。对坐标轴、模板图、解析碎片、共享对照、标准统计输出等常见自动假阳性，要主动寻找并写明排除依据。

#### 0. Evidence Gate

先读 `review_evidence.json`。必须逐项处理：
- `coverage_manifest.must_address`
- `high_findings`
- `deterministic_findings` 中的 duplicate columns、cross-sheet reuse groups、decimal precision mismatch
- `main_figures_to_check`

低风险结论必须明确覆盖所有必查项；不能只写“均为假阳性”。若证据包缺失或关键文件无法读取，除非已有清晰证据支持低风险，否则按高风险处理。

#### 1. Review Order

1. 读论文 PDF：提取每个主图/关键补充图的实验设计、样本量 n、是否独立实验、共享对照说明、关键方法/试剂/伦理/时间线信息。
2. 独立审计源数据：先查源数据，再看自动告警。
3. 复核图像重复、图像拼接、数据异常、参考文献异常。
4. 做图文一致性核查：主图的可读数值、曲线/柱状趋势、样品标签必须与源数据一致。
5. 汇总真实问题和已核实假阳性，生成面向审核人员的中文 JSON。

#### 2. Source Data Audit

必须覆盖所有 xlsx/xls/csv/docx 源数据；docx 表格需注意合并单元格造成的重复值假象。读取 docx 表格时，合并单元格会在合并范围内重复同一值（如跨列合并后 3/4/5/6 列均显示相同内容），这是格式伪影而非数据重复，判定前须确认来源是 docx 还是 xlsx。

样本量核查：
- 主图 Fig.1-Fig.6+ 必查；补充图按风险抽查。
- 对每个主图 sheet，记录“论文声明 n=Y，实际数据 n=Z”。
- 不可仅查一个主图 sheet 就得出“样本量一致”结论；必须覆盖论文实际包含的全部主图，若有 Fig.1-Fig.6+，这些主图都要查。历史失败案例：某论文 156 个 sheet 中仅查了 Fig.6H（n=6 一致），遗漏了 Fig.4A(n=5)、Fig.4B(n=3) 和 Fig.5A/6A 跨图复用。
- 主图样本量与论文声明不一致，通常支持高风险。

跨图数据复用：
- 对不同 sheet/图号中长度 >=3 的数值列做相同值比对。
- 若不同实验、不同样品、不同条件的数据列逐值相同，支持高风险。
- 使用"共享横轴/时间轴/共享对照"解释前，**必须先打开 xlsx 确认共享列的物理含义**：读取列头名称、查看数值范围和单位，确认该列是自变量/横轴（如时间点、浓度梯度、剂量）还是因变量/测量值（如吸光度、细胞计数、表达量）。
- 若共享列是测量值列，不能用"共享横轴"解释；只有论文/图注/源数据明确支持同一实验共享对照时，才可作为非异常解释。
- 处理组数据也相同，或论文声称为不同实验/样品/条件时，不能用"共享对照"排除。

补充材料数据完整性：
- 补充数据文件（xlsx/docx/csv）是作者提交的官方评审材料，其数据完整性是独立审查对象，不能仅关注"正文图表有没有错"。
- 补充材料中跨 sheet 的整块数据复制、逐值复用（即使不同实验声称），是独立的高风险证据。不能以"正文图表可能用了正确数据/源数据文件错放"为由将此类问题降级。
- 判定流程：当补充材料 xlsx 中发现不同 sheet（对应论文声称的不同实验/条件/样品）数据逐值相同时：
  1. 先确认这些列是测量值列还是哑变量/横轴列（打开 xlsx 读列名和数值范围）。
  2. 若为测量值列且论文在不同 sheet/图号中声称为独立实验 → 支持高风险。
  3. 正文图使用了哪个数据源是图文一致性核查的问题，不能作为补充材料数据复用的豁免理由——正文核对与补充材料审计是两项独立检查。
  4. 唯一豁免：若作者/期刊明确说明某 sheet 为模板、示例或参考数据（通常在 sheet 名或注释中标明"reference""example""template"），可在写明依据后排除。
- 例外：分组哑变量列（one-hot encoding，仅含 0/1/空值）或共享横轴列（时间点、浓度梯度等自变量）的高重叠率可为假阳性，但必须在 data_review 中写明每个被排除列的列名、取值范围和判定依据。

列对与恒等依赖：
- 关注跨组 >80% 重叠、R²>0.99999 且斜率≈1/截距≈0、CV=0、等差/等比序列、重复长小数、末位数字集中、SD/SE 过度规则。
- 横轴、时间轴、波数轴、基因分类列、cluster ID、通路背景大小、校正后 p 值截断、归一化对照=1.0、问卷有限取值可为正常模式，但必须结合研究领域和具体列名确认。

小数精度：
- 同类测量跨 sheet 出现 2 位 vs 9 位等强不一致，或多列长小数完全统一，支持高风险。
- 汇总均值 vs 原始仪器时序、不同仪器输出、文献提取统一精度可解释，但需说明依据。

小数尾串继承/插入（必须主动检查）：
- 不只检查“小数位数是否一致”，还要检查“数字内容是否被继承”。对同一图、同一 sheet、相邻子表或对应组（如 plasma vs serum、pre vs post、不同处理组的同一行样本），逐行比较小数部分。
- 若右侧/后续测量值大量保留、包含、插入或改写左侧/前序测量值的小数尾串（例如 0.645 -> 0.7645、0.7546 -> 0.67546、0.533 -> 0.4533），且发生在不同测量类型或应独立生成的实验值之间，支持高风险。
- 涉嫌数据规范性异常时，要特别检查“右侧对应组/后续组的大部分数据小数部分像是随机插入一个或两个数字”的模式；这类规律性分布不能被笼统解释为普通小数精度差异。
- 判定阈值：同一对应组中 >=50% 行出现 3 位以上小数尾串被包含/继承，或 >=80% 行末 2-3 位一致，且不能由固定编码、分组标签、时间轴、浓度梯度、样本编号或统一格式化解释时，应写入 data_review 作为数据规范性异常。
- 低风险结论必须说明是否检查过此模式。不能把这类问题泛化为“普通小数精度差异”“仪器输出精度不同”后直接排除；必须给出列名、行数、例值和排除依据。

统计自洽：
- 扫描末位数字和 SD/SE 规律；必要时核算均值/SD/n/p 值。
- 发现“所报均值在所述例数下数学上无法成立”等问题，应写入 data_review 或 methodology_review；报告中将其解释为“研究设计与统计核查”。

- `python3 /home/library/.claude/skills/paper-batch-review/scripts/forensic_checks.py scan-digits --excel-dir "<原始数据目录>"` — 末位数字/SD 规律性扫描
- `python3 /home/library/.claude/skills/paper-batch-review/scripts/forensic_checks.py scan-decimal-tails --excel-dir "<原始数据目录>"` — 对应组/相邻子表小数尾串继承或插入扫描
- `python3 /home/library/.claude/skills/paper-batch-review/scripts/forensic_checks.py verify-stats --input <triples.json>` — GRIM/GRIMMER/p 值核算

#### 3. Figure-vs-Source Check

主图必须与自己的源数据逐图对照。这是必须执行的独立核查步骤，不能因为统计告警已全部排查就跳过。

操作步骤（必须执行）：
1. 用 `fitz.open()` 渲染论文 PDF 中包含主图的页面为 PNG，再用 Read 工具查看渲染图像。
2. 同时从对应 xlsx sheet 中读取数据，核对关键数值（如柱状图的高度值、曲线的峰位和相对强度、散点分布范围、坐标轴量级）。
3. 覆盖范围：至少核查 3 张主图（或全部主图，以较少者为准）；若论文含补充材料 PDF，再抽查至少 2 张有源数据对应的补充图。
4. 在 data_review 中明确写出每张核查图的结论，例如”Figure 3a 渲染图中 Ptδ+-Ptδ–/Ti 的 LSV 曲线峰值约 540 mA/cm²，源数据 Figure3a sheet 中最大值为 541.2 mA/cm²，趋势和量级一致”。

重点查：
- 图中柱高/曲线/散点趋势与源数据数值相反或对调。
- 同一数据列在两个图中使用不同样品/条件标签。
- 图注声明独立实验，但源数据为同一批数据。
- 坐标轴范围、单位与源数据不匹配。
- 图中数据点数量与源数据行数明显不符。

此类图文或标签矛盾是独立高风险证据，不要被”共享横轴”解释带偏。仅查看 annotation 标注图不算完成此步骤——必须对比论文渲染图像与源数据数值。

#### 4. Image Review

对 report.json 中每组 image duplicate / image_splicing 都要查看标注图或原图。

高风险图像证据：
- PHash=0 跨页真实图像重复，排除空白页、小缩略图和装饰元素。
- template_score >=0.9 且视觉确认为相同内容。
- 不同实验声称下的同一照片、同一 blot/gel、同一显微图重复。
- 拼接标注处背景灰度、曝光、分辨率或压缩质量明显不连续。

常见假阳性必须视觉确认后才可排除：
- PDF 原图与正文嵌入版重复。
- 坐标轴模板、ROC 标准结构、UMAP/tSNE 同一嵌入不同着色、化学结构图、fMRI 标准脑模板、文献计量图、有限元模型、微小缩略图。
- 生信流水线图像相似时，需确认轴标签、样本、点位/曲线/颜色含义不同；实际数据内容相同不能排除。

#### 5. Reference Review

区分 PDF 解析碎片和真实引用异常：
- 乱码、断行、单词碎片、双栏拼接、缺 DOI 但著录完整，通常是解析/数据库限制。
- 完整可读著录 + DOI 不存在、DOI 指向完全不相关文献、题名/作者/期刊明显不一致，支持引用异常。
- 批量层面：当 >5 个完整可读条目的 DOI 查无此文，且 DOI 前缀/格式与对应期刊或出版商明显不匹配时，支持引用异常；少量完整可读 DOI/题名/作者实质不一致也可独立支持异常。
- 高风险引用问题需给 1-2 个具体例子；假阳性简写，不要堆 DOI 查验过程。
- CrossRef 接口调用失败（timeout / rate-limit / 500 错误）不构成引用异常证据。如果 report.json 中参考文献问题全部或大部分标注为 doi_unverified / lookup_failed，应直接判定参考文献维度低风险，不要把接口故障写成引用问题。

#### 6. Verdict Rules

建议高风险（任一成立）：
- 主图样本量与声明不符。
- 不同实验/条件/样品的数据逐值复用。
- 真实图像重复或拼接迹象。
- 同类测量跨 sheet 小数精度强不一致。
- 同图/同 sheet 对应组或相邻测量之间出现系统性小数尾串继承、插入或改写模式，且无法由编码/横轴/统一格式化解释。
- 非统计/分类/轴变量中的 CV=0、恒等依赖、异常规则序列、末位数字/SD 规律性异常。
- 图与源数据数值或样品标签矛盾。
- 完整可读参考文献存在 DOI/题名/作者/期刊实质不一致。

建议低风险（全部成立）：
- 已读 PDF 并核对主图声明、样本量和关键方法。
- 已审计源数据，未发现独立问题。
- 每条 HIGH 和每个 must_address 均有具体位置、现象、解释和核查依据。
- 图像/数据/参考文献问题均有可验证的合理解释。
- 低风险理由不是泛泛“假阳性”，而是逐类覆盖。

#### 6.0 Final Convergence Flow

复核结论必须经过最终收敛层：

1. r1 第一轮给 `低风险` 时，必须先进入 Reviewer2 对抗性检验，再进入 judge agent。
2. r1 第一轮给 `高风险` 时，跳过 Reviewer2，直接进入 judge agent。
3. judge agent 读取 r1、必要时读取 Reviewer2，并输出最终 `高风险` 或 `低风险`。PDF 和 DB 写回只能使用 judge 结果。
4. r1 或 Reviewer2 的结果都只是候选结论，不能直接写报告/写库。
5. judge 若发现 r1/r2 证据不足或互相矛盾，应基于可核查证据重新收敛；材料缺失本身不是风险证据。

#### 6.1 材料不完整 / 源数据缺失（Missing Materials）

材料不完整、无 xlsx、无 evidence、源数据不可读或只提供部分材料，**本身不是风险证据**，也不再作为独立终态写 `待补料/status=3`。

**处理原则**：
  1. 有什么材料审核什么材料：PDF、图像、正文/图注、补充材料、可读表格、参考文献、初检标记都应尽量核查。
  2. 如果在可用材料中未发现具体完整性问题，结论应写 `低风险` / `建议低风险`，并按低风险规则进入 Reviewer2 对抗性复核。
  3. 只有发现具体、可定位、可解释为完整性问题的证据，才写 `高风险` / `建议高风险`。
  4. 报告可以客观说明“未提供可扫描表格/源数据，因此该类列级审计未执行”，但这只是覆盖范围说明，不能作为高风险、待补料或拒绝低风险的理由。
  5. 真正的程序错误、review_error 占位、无法解析的内部失败，不生成正式 PDF/DB 写入，应重跑；不要把程序错误伪装为论文风险结论。

#### 7. Report Writing

输出 JSON 字段：doi/result/trigger/image_review/data_review/ref_review/methodology_review/verdict/reason。

正式 PDF 默认采用简明标准：先结论，再列确认问题、核查依据和 1–4 张关键截图。确认问题仍须完整包含“问题位置/问题类型/具体情况/需关注原因/核查依据”，但每项只保留支撑结论所需的最少事实和代表性数值。已排除项仅写类别、数量和一句理由；低风险维度最多一段。综合评估不重复长篇技术过程，并明确风险提示不等同于对主观意图的认定。常规报告目标约 3–6 页；仅调试历史问题时可设置 `REVIEW_REPORT_VERBOSE=1` 恢复详细版，不用于正式交付。

面向审核人员写法：
- **先写确认的问题，再写已排除的假阳性**。每个 review 字段（image_review/data_review/ref_review）的文本结构必须清晰分隔：先集中写确认的问题（含”核心发现””值得关注””数据完整性问题”等标记词），再集中写假阳性（含”假阳性””属正常””可解释””不构成”等标记词）。禁止交替混写。
- 每个确认问题必须按下列五项固定顺序写；一项都不能省略：
  1. `问题位置：` 原文文件名和页码，并写明 Fig./Table/公式编号；涉及源数据时补充文件名、sheet、列和行范围；参考文献写编号。
  2. `问题类型：` 用通俗类别概括，例如“公式计算与表格不一致”“不同实验使用了相同数据”“图注样本量与源数据不一致”。
  3. `具体情况：` 把论文原值与复算/核查值逐项对照，不能只写“存在异常”“不自洽”或内部规则名。
  4. `需关注原因：` 说明它具体影响哪个参数、图表、实验比较或论文结论；不要笼统写“影响可靠性”。
  5. `核查依据：` 说明使用了原文、图注、源数据、原始图片或哪一步计算进行验证。
- 涉及公式或统计计算时，`具体情况` 必须给出公式、代入值、中间计算、计算结果、论文报告值和差异；涉及百分数/小数、次数/年份等尺度时必须说明单位或尺度。
- 英文报告使用同样顺序：`Location → Issue type → What was found → Why it matters → Verification basis`，不得把中文的模糊概括直接逐字翻译成英文。
- `reason`（综合评估）中每个确认的高风险问题**必须带具体位置**，不可只写类别。具体要求：
  - 图像问题：写明哪张图/哪个页码（如”Fig.3a page 5 与 Fig.S2 page 12”）
  - 数据问题：写明哪个文件/sheet/列/行及数值举例（如”MOESM4 Fig.2f 中 FeCl2 与 IONPs 的 6 个 UA 生成值在 9 位小数上完全一致(0.045454545)”）
  - 参考文献问题：写明第几条引用及具体不一致（如”第12条引用 DOI 指向完全不相关文献”）
  - 不可接受：reason 只写”存在数据复用””图像重复””引用异常”而不说具体位置
- 对真实问题给具体 sheet/列/行/数值例子；对假阳性保持简洁。
- 不要在报告中出现内部术语、文件名、字段名或流程信息。具体禁止：`report.json`、`image_duplicates`、`image_splicing`、`data_anomalies`、`reference_issues`、`cross_group_duplicate`、`value_recycling`、`terminal_digit`、`sd_regularity`、`PHash`、`template_score`、脚本路径、角色称谓、多通道流程痕迹。使用对应的中文描述（如"初检报告""图像重复""跨组重复""首位数字分布"等）。
- 也不要使用自动化/编排层的内部名词：`evidence bundle`、`evidence_path`、`coverage_manifest`、`coverage_validator`、`must_address` 等。直接说"初检发现""自动检测出的""初检标记的""初检环节"等中文描述。
- 不得暴露 review_evidence.py / coverage_validator.py / generate_review_report.py 等脚本路径、模块名或流水线角色（agent 自身、reviewer、judge、观察员等）。
- 禁用意图性词汇：造假、篡改、伪造、编造、不端、欺诈、操纵。使用：异常、完整性问题、规范问题、非自然生成、重复或异常。

最低具体性：
- image_review：匹配总数；每组页码/图号/结论；拼接标注是否确认。
- data_review：主图样本量核查、跨图复用、列对扫描、精度/末位数字/统计自洽结论；每个高风险发现的位置和例值。
- ref_review：高风险引用问题数量；1-2 个例子；明确解析问题 vs 真实异常。
- methodology_review：仅有方法、时间线、伦理、样本量前后矛盾等发现时填写；无则空字符串。

不可接受的写法：
- "未发现图像重复异常。"（无页码、无匹配数量、无核查过程）
- "数据异常标记经核查均为假阳性，无数据完整性问题。"（无文件名、无具体值、无推理）

合格示例：
- image_review: "共检出8组图像匹配。其中7组为论文正文页面(page_3/4/6/8)与投稿原始图片文件的正常匹配，属假阳性。第8组(page_5 vs page_12)经视觉核查为不同类型图像（柱状图 vs 散点图），属模板匹配假阳性。"
- data_review(高风险): "关键发现：Figure 5I源数据（CHX chase蛋白降解实验，声明n=3）中，Ctrl-sh组的第1和第2列数据完全一致（6个时间点，精确到6位小数：1.000000, 1.079898, 0.370102, 0.163102, 0.188794, 0.061887）。生物学重复实验产生完全相同的数值在统计学上极不可能。"
- data_review(含统计): "末位数字核查：Source Data Fig.4.xlsx / 'Fig4c' 的肿瘤体积列(n=120)末位数字高度集中于0与5，与自然测量数据预期分布明显不符。统计量核算：表2处理组所报均值在所述例数下数学上无法成立。"

假阳性解释简洁化：说明类别、数量和一行理由即可，不要逐条列举每个 DOI 查验过程或解析片段。
