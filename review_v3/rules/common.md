# 通用复核规则

## 立场
- 目标是基于可核验事实，对本分片每个核查项给出结论。初检只是线索，初检高风险本身不是证据；也不能为支持初检结论倒推异常。
- 对坐标轴模板、解析碎片、共享对照、标准统计输出等常见自动假阳性，要主动寻找并写明排除依据。
- 同样要主动检验“合理解释”是否真的成立。下列软解释单独不能排除一项告警，必须配具体数字（n、r、斜率、列名、单位、跨文件对照）：
  “标准格式/软件导出格式”“实验惯例/归一化惯例”“测量分辨率有限”“同一患者分入多组”“1/3 数学必然”“Benford 偏离正常”“大整数存储”。
  反证不成立时，该线索维持为问题。

## 结论的严重程度（severity）
- 按下文“定级规则”区分 substantive（实质问题）与 minor（规范问题）。minor 也必须记录并给出更正建议。
- 没有确认统计量、数据批次、评估时间点与汇总方式相同之前，不得仅因误差棒与表内标准差数值不同就认定数据错误。

## 材料不完整
- 有什么材料审什么材料。没有源数据、文件不可读或只有部分材料，本身不是风险证据；该项写 not_applicable，并在 basis 中写明缺什么、核查了哪些替代材料（正文、图注、表格、图像）。
- 不要循环搜索不存在的文件，不要把全部曲线数字化后穷举。
- 真正因时间或工具故障无法完成的核查写 unresolved，并在 note 写明缺口。未执行的核查不得写成已完成。

## 台账（唯一有效的输出）
- 每完成一项或一批核查，立即用 `pv3 ledger update` 写入，不要攒到最后。会话随时可能因轮数用完被暂停，未写入台账的工作会丢失。
- 写入格式（JSON 列表，可一次写多条）：
```
pv3 ledger update <<'EOF'
[{"id": "条目id", "status": "issue|cleared|not_applicable|unresolved",
  "severity": "substantive|minor（仅 issue）",
  "location": "文件名+页码+Fig./Table 编号；源数据写文件、sheet、列、行范围；文献写编号",
  "issue_type": "通俗类别，如“不同实验使用了相同数据”",
  "finding": "原值与核查值逐项对照；公式问题写公式、代入值、计算结果和论文报告值",
  "why": "具体影响哪个参数、图表、比较或结论",
  "basis": "用了哪些原文、图注、源数据、截图或计算进行验证（cleared 也必须写具体依据）",
  "evidence": [{"path": "pv3 render/view 生成的截图路径", "caption": "截图说明"}],
  "note": "补充说明"}]
EOF
```
- 发现台账外的新问题，用 id `new:<简短英文标识>`，并给出 `"dimension": "image|data|ref|methodology"` 和 `"title"`。
- 同一类多个告警可以在一条中说明，但 basis 必须列出覆盖的 sheet/组/通道、代表原值和结论，不能只写“其余均正常”。
- 截图必须是看得清问题的局部：保留图号、表头、坐标、图例和必要对照；裁剪前先看整页确定坐标，不要猜测；整页缩略图不算定位。

## 材料范围
- 只核查本论文的材料：`pv3` 资料包、原始材料目录与初检提取的图片。不要读取系统代码、其他论文、历史复核报告或 memory 文件（会被拒绝）。
- 复核必须独立形成结论，不得引用或沿用任何既往对本论文的结论。

## 效率要求
- 先用 `pv3` 读预先抽好的资料：`pv3 info`、`pv3 page`、`pv3 find`、`pv3 captions`、`pv3 files`、`pv3 sheet`、`pv3 colcmp`、`pv3 render`、`pv3 view`。不要自己写脚本重抽 PDF 文本。
- 能在一个命令里完成的多项读取合并为一次调用；长输出先用 grep/head 收窄。
- 查看图片前先用 `pv3 render`/`pv3 view` 生成缩放后的 PNG，再用 Read 查看；需要细节时裁剪局部，不要读原始大图。
- 数值复算用解析公式或向量化计算；禁止组合爆搜和无界枚举；自写脚本加 `timeout 120`。
- 外部查询（CrossRef）同一失败不要反复重试；超时或限流不是引用异常证据。
- 遇到不熟悉的判定情形，用 `pv3 mem "关键词"` 检索既往复核经验。

## 用语
- 禁用：造假、篡改、伪造、编造、不端、欺诈、操纵。使用：异常、完整性问题、规范问题、非自然生成、重复或异常。
- 台账文字面向审核人员，用中文平实描述，不写内部字段名、脚本名、哈希值或流程角色。
