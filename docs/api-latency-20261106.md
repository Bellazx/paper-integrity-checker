# API 75 分钟预算与提速验证（2026-11-06）

## 执行规则

- 单篇 API 任务仍使用 75 分钟总预算，末尾保留原有 5 分钟生成报告；复审最多使用到第 70 分钟。到复审截止点后，使用已经核实并保存的结果生成报告，未完成项如实保留。
- API 模式下不再额外扣除 v3 的 15 分钟调查/补查预留和 6 分钟评级/截图预留。独立批量入口保留原配置；阶段软收尾、无进展判断和单次调用保护仍存在。
- 截止时间耗尽后不再发放额外 60 秒；报告排队、模型重试、英文子进程都使用剩余预算。超时或取消时结束英文渲染进程组，避免后台继续出文件。
- `zh` 只生成中文，`en` 只生成英文，`both` 并行生成两份。初检并行发生在受检测超时约束的子进程内；复核两种语言各有独立渲染进程。两份都成功才完成双语任务。
- 每篇复核结束即可开始渲染，避免等待同批其他论文。英文链接入库并核验后才写复核完成状态，英文请求不返回虚构的中文链接。

## 实现

- `modules/initial_report_bundle.py`、`api/services/detection_reports_worker.py`：按语言生成、双语并行、已有英文初检复用、每种语言计时。
- `scripts/generate_english_report.py`、`api/services/report.py`、`utils/llm_client.py`：英文进程隔离、相同发布校验、临时文件成功后原子替换、模型剩余时间约束。
- `review_v3/engine.py`：API 复审统一截止点；主图逐页浏览进入补查；先对明确定位的图表和源数据生成证据，缺口再交给模型。到点恢复包含已经保存的截图，且不改变已核实结论。
- `review_v3/autocrop.py`：自动优先路径要求明确图表位置，不能只找到部分被引用图表，不能截断图注；模糊定位仍需模型。
- `review_v3/workbook_cache.py`、`review_v3/tools/pv3.py`：`pv3 sheet/colcmp` 复用完整工作表。缓存按路径、文件大小、纳秒修改/变更时间、inode、sheet 和解析版本区分；保留浮点数、日期、布尔值和空单元格。完整读到 EOF 后才原子发布，预览一部分行不会留下完整缓存。源文件变化使缓存失效。

## 实测

使用 `1d91ffd5` 在 **10 月 29 日保存的材料和审核结果**，输出全部位于 `experiments/api-latency-20261106/`。没有覆盖业务报告、更新业务数据库或重跑整篇调查。这是局部性能测试，不是今天五篇重跑的独立复现。

### 工作表（约 11 MB 工作簿，Figure 2H，50,153 行）

| 测试 | 秒 |
|---|---:|
| 不使用缓存，第一次完整读取 | 12.3066 |
| 不使用缓存，第二次完整读取 | 12.2862 |
| 第一次读取并建立缓存 | 14.0329 |
| 缓存后第一次完整读取 | 1.0681 |
| 缓存后第二次完整读取 | 1.0660 |

五次输出的逐行内容摘要一致：`943dd300fdf7347395cae6f4c61503e0dffadeb50efc2efbc8cf6c7bddbe9c04`。重复读取约缩短 91%；首次建立缓存增加约 1.7 秒。一次冷读取加一次缓存读取约 15.10 秒，原来的两次读取约 24.59 秒。收益限于走这些工具并重复读取的工作，不能换算成整篇复审缩短 91%。

### 真实模型调用与 PDF 渲染

| 测试 | 串行（秒） | 并行（秒） |
|---|---:|---:|
| 第一轮复核报告 | 27.280 | 26.766 |
| 加入数值保留校验后的复核报告 | 41.773 | 46.537 |
| 双语初检报告（复用已有初检 JSON） | 99.182 | 116.752 |

本样本**没有证明双语并行稳定提速**，两轮模型请求的响应与补译时间存在差异。并行排除了语言之间的强制串行依赖，但仍受模型服务、重试及共享资源影响。

第一轮英文翻译漏掉了源文中的 `12.5`。随后加入按字段检查小数数值和一次定向补译，修复了句末英文标点的识别问题及修复提示的输出约束。最终复核样本没有丢失检查到的小数数值；这只是数值保留检查，不等于完整翻译语义验证。串行、并行中文提取文本一致，四份复核 PDF 均包含 3 张证据图片，图片内容摘要集合完全一致。中英文输出共用同一份已保存结论。

复现实测：

```bash
venv/bin/python scripts/benchmark_review_latency.py \
  --workbook data/input/20261029-task/20261029-2837a26f/10.1038_s41467-024-45562-y/source_data/s41467-024-45562-y-Source_Data_v1.xlsx \
  --review data/tasks/20261029-2837a26f/review_results.json \
  --live-reports \
  --out experiments/api-latency-20261106/new-run
```

`--live-reports` 会发起真实模型请求；不加此参数时，工作簿对比不调用模型。`--live-initial <report.json>` 可单独比较初检 PDF。每次对比使用新的输出目录以区分冷缓存和热缓存。
