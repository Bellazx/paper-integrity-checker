# 复核会话的有界收敛（2026-10-27）

`error_max_turns` 表示一次 CLI 会话消耗了允许的模型交互轮数，不是论文
有风险的证据。旧的 1027 批次运行器至少给每次调用 160 轮，并叠加会话续跑、
阶段重试和 worker 重试；协调器只检查 PID 是否存在，最后还会持续轮询
`needs_recovery`，导致任务长时间无最终状态。

## 当前行为

- API、`run_review_single` 的批量调用，以及 1027 专用批次共用
  `api/services/review_cli.py`。
- 每次阶段调用最多三个步骤：正常核查（配置轮数，默认 80；最多 900 秒）、
  补齐未解决项（24 轮、480 秒）、禁用工具的结果整理（1 轮、180 秒）。
  外部配置更短的超时仍生效，配置 unlimited 也不能取消这些硬上限。
- 补查和整理沿用同一会话，使用 `REVIEW_FALLBACK_MODEL`（默认 `MiniMax-M3`）。
  主模型配置保持不变；CLI 的 unrecognized_model 警告本身不证明调用失败。
- 1027 批次在启动步骤前保存预算和会话，重启与外层重试不能重新获得已用预算。
  成功返回的草稿仍须通过完整的证据覆盖校验；工具关闭不会补造核查事实。
- 综合复核修补最新的实质候选结论，而非重复修补第一轮。后续过程失败不能
  覆盖已发现的实质分歧。只有两个实质复核各自通过校验、结论相同，且没有
  更新的实质综合结论时，才允许在综合调用失败后保留已验证共识。
- worker 总生命周期默认上限 7200 秒，可用 `REVIEW_WORKER_MAX_SECONDS` 调整。
  超限清理整个子进程树；重试最多三次，不退还次数。耗尽后明确记录
  `needs_recovery` 和原因，协调器在全部任务完成或明确失败后退出。
  `finished=true` 仅表示全部成功；`settled=true` 包含已停止的失败任务。

## 发布边界

流程必须停止或完成，但不能保证缺少证据时强行给出论文风险结论。
最终输出若仍缺关键证据，保留具体未解决项，不生成正式 PDF、不写回风险结论。
已有终稿、证据、原始材料和会话记录不因恢复而删除。

## 本次运行恢复

`scripts/recover_1027_bounded_sessions.py` 只迁移戴大伟两篇未完成任务；保存迁移前
状态，保留会话和证据，给一次新运行机会。迁移标记防止重复重置预算。
线上 API 必须在空闲时重新加载；修改文件本身不会更新已导入模块的进程。

## 验证

`tests/test_review_cli_convergence.py` 覆盖连续达到轮数上限、禁用工具收尾、
断点预算不重置、超时/取消清理、DOI 错配、流程错误不能当结论、
最新候选结论保留、覆盖门禁、worker 总时限，以及批次耗尽后退出。
